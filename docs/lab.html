Stage 2 · setup-vm.sh

The lab VM

One LXD virtual machine is the whole lab: its own kernel (for the simulated radios), Docker for boardfarm's WAN side and local-noc, and nested LXD for the gateway, the extenders and the clients.

./setup-vm.sh all          # create + provision opensync-lab-<MMDD>
./setup-vm.sh status       # VM, radios, containers, check results, the topology view URL
./setup-vm.sh shell | stop | start | delete

Provisioning

create makes the VM (Ubuntu 24.04, 4 CPU, 8 GiB, 64 GiB, UEFI without secure boot). provision pushes the guest scripts to /opt/opensync-lab and runs them as root; every one is safe to re-run.

→ → → →

00-base.sh

Packages, Docker, snap LXD (held), uv, lxd init on btrfs, the kernel modules for mac80211_hwsim (a reboot if they had to be installed), and a unit that keeps Docker's firewall from eating LXD bridge traffic.

10-hwsim.sh

The radio pool: mac80211_hwsim with 24 radios on 2 channels, named virt-wlanN, loaded at boot. Containers take radios from the pool as physical NICs (mv3 three, each extender two, each client one); radios a deleted container leaves behind are reclaimed. All radios share one medium: any BSS is visible to every radio.

20-boardfarm.sh

boardfarm-lab-staging at a pinned commit (a bundle from the host), this repo's patches to it, a uv venv, and the lab config opensync-lab.json. bf-lab builds and starts the WAN side of one vCPE: dhcp-cpe1 (Kea), wan-cpe1 (NAT), lan-cpe1. Boardfarm is used only for this; its testsuite is not run. A rebuild service keeps the WAN side healthy across reboots and makes wan-cpe1 reject non-lab IPv6 at once when the host has no IPv6 upstream.

25-local-noc.sh

The local cloud as a Docker container on boardfarm's WAN network at 10.101.0.40, so the gateway reaches it through its WAN like the real cloud, with the mesh orchestration for the gateway mv3 and the web UI on port 8640. The step waits for the redirector, the controller and the UI to answer. See local-noc.

The topology view on the host

Docker publishes the UI port on the VM; setup-vm.sh reserves the VM's address on lxdbr0 and adds an LXD NAT proxy device noc-ui from the host's primary address (a NAT proxy into a VM cannot listen on 0.0.0.0). setup-vm.sh status prints the URL.
